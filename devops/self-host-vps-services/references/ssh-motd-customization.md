# SSH MOTD Customization

How to disable Ubuntu's verbose MOTD (Message of the Day) and replace it with neofetch on SSH login.

## Problem

Ubuntu's default MOTD displays verbose system information on SSH connect:
- "Welcome to Ubuntu 24.04.4 LTS..."
- Documentation links
- System load, memory, disk usage (via landscape-sysinfo)
- Ubuntu news/ads
- ESM Apps notifications
- Update counts

This output is long and repetitive. User preference: replace with neofetch.

## Solution

### 1. Disable Ubuntu MOTD scripts

Ubuntu MOTD is generated by executable scripts in `/etc/update-motd.d/`. Remove execute permission to disable all:

```bash
sudo chmod -x /etc/update-motd.d/*
```

Verify:
```bash
ls -la /etc/update-motd.d/
# All files should show -rw-r--r-- (no x flag)
```

### 2. Add neofetch to .bashrc with SSH detection

Add neofetch auto-run to `~/.bashrc` with SSH connection check (prevents double-run in nested shells):

```bash
cat >> ~/.bashrc << 'EOF'

# Auto-run neofetch on SSH connect
if [ -n "$SSH_CONNECTION" ] && [ -z "$NEOFETCH_DONE" ]; then
    export NEOFETCH_DONE=1
    neofetch
fi
EOF
```

The `NEOFETCH_DONE` flag prevents neofetch from running twice if the user sources `.bashrc` manually or spawns a nested shell.

### 3. Check for existing neofetch/fastfetch entries

Before adding, search for existing entries to avoid duplicates:

```bash
grep -n "neofetch\|fastfetch" ~/.bashrc
```

If duplicates exist, remove the old entry first:
- For a single line: `sed -i '<line-number>d' ~/.bashrc`
- For a range: `sed -i '<start>,<end>d' ~/.bashrc`

### 4. Remote VPS configuration via SSH

When configuring a remote VPS (e.g., root@45.137.70.30 password 3551):

```bash
# Disable MOTD
sshpass -p '3551' ssh -o StrictHostKeyChecking=no root@45.137.70.30 \
  'chmod -x /etc/update-motd.d/*'

# Add neofetch to .bashrc
sshpass -p '3551' ssh -o StrictHostKeyChecking=no root@45.137.70.30 \
  'echo -e "\n# Auto-run neofetch on SSH connect\nif [ -n \"\$SSH_CONNECTION\" ] && [ -z \"\$NEOFETCH_DONE\" ]; then\n    export NEOFETCH_DONE=1\n    neofetch\nfi" >> ~/.bashrc'

# Verify
sshpass -p '3551' ssh -o StrictHostKeyChecking=no root@45.137.70.30 \
  'tail -n 6 ~/.bashrc'
```

## Pitfalls

- **Duplicate neofetch entries cause double output.** Always grep `.bashrc` for existing neofetch/fastfetch before appending. If found, remove the old entry first.
- **Direct `source ~/.bashrc` in a running Hermes gateway session is blocked** (prevents accidental gateway restart). The change takes effect on the next SSH session automatically — do not test with `source` inside the gateway process.
- **fastfetch vs neofetch variable naming.** When replacing fastfetch with neofetch, also rename the guard variable (`FASTFETCH_DONE` → `NEOFETCH_DONE`) to prevent confusion and ensure the guard works correctly.
- **MOTD scripts with symlinks.** Some MOTD scripts (e.g., `50-landscape-sysinfo`) are symlinks. `chmod -x` removes execute permission from the link itself, effectively disabling it. Do NOT follow symlinks and chmod the target — that may break other systems.
- **User vs root .bashrc.** When configuring a VPS as root, the neofetch entry goes in `/root/.bashrc`. For non-root users, it goes in `/home/<user>/.bashrc`. Match the target user's login shell.
